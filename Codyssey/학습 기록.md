# B1-1 학습 기록

최초 기록일: 2026-09-19
최근 갱신일: 2026-09-19

이 파일은 지금까지의 대화에서 확인된 사용자 설정, 현재 진도, 학습 이력을 정리한 기록이다. 전체 발언의 축어록은 아니다. 모델이 바뀌어도 매 답변 전에 읽고 수업에 적용한다. 사용자의 최신 지시를 우선한다.

## 1. 바로 이어갈 위치와 최근 확인된 진도

- 학습 설정을 마쳤다. 같은 설정 질문을 처음부터 반복하지 않는다.
- **최신 학습 방향 (2026-09-19 사용자 요청)**: **미션 상세를 더 공부한 뒤 2단계 HTML 구현을 진행한다.** 다음 학습을 바로 코드 작성으로 시작하지 않는다.
- 구현 순서는 HTML → CSS → JavaScript를 유지한다. JavaScript 문법 학습은 잠시 미뤄두고 HTML/CSS 요구사항을 먼저 살펴본다. 앞서 정한 학습·구현 병행보다 위의 최신 요청을 우선한다.

#### 2단계 이후: 미착수

- 2단계(HTML 시맨틱 마크업), 3단계(CSS), 4단계(JS), 5단계(API)의 기능 구현은 미착수.
- 6단계 체크리스트 중 현재 진도까지의 Git 커밋·푸시는 완료. GitHub Pages 배포 및 최종 브라우저 검증은 미완료.

### 1-2. 다음 이어갈 작업 (구체적 지시)

**다음 학습**: `미션.md`의 상세 요구사항을 한 항목씩 읽고 의미를 공부한다. 2단계 구현은 사용자가 미션 상세를 더 공부한 뒤 진행한다.

- 사용자가 별도 위치를 지정하지 않으면 `4. 기능 요구 사항 → 2. HTML 구조 (시맨틱 마크업)`을 다음 시작점으로 제안한다. 이는 다음 수업의 제안이며, 해당 절의 상세 학습을 마쳤다는 뜻이 아니다.
- 첫 설명은 “전체 레이아웃을 div로만 감싸지 않고 시맨틱 태그를 사용한다”는 요구사항의 의미부터 짧게 다룬다. 기존에 설명한 정의를 길게 반복하기보다 작은 예시로 요구사항을 구체화한다.
- 미션의 필수 조건과 README·예시 코드의 설계 선택을 구분한다. 설정 설문, 파일 연결, Live Server 확인을 처음부터 반복하지 않는다.
- 사용자가 공부할 문장이나 항목을 고르면 그 위치를 우선한다.

### 1-3. 이전 대화에서 완료된 개념 확인 이력

아래는 이전 도구와의 학습 기록에서 이해 확인 완료로 인계된 개념이다. 이번 재개 대화에서 해당 개념들을 다시 평가한 것은 아니다.

| 개념 | 확인 방법 및 결과 |
| :--- | :--- |
| 미션 전체 흐름 | `"사용자 이벤트 → DOM 조작 → 화면 변화"` 3단계 흐름을 자기 말로 확인. |
| 외부 API 연동 | GitHub API 실시간 요청 및 4가지 상태(로딩/성공/빈 상태/에러) 구분 확인. |
| 최종 결과물 | 반응형 웹의 의미, 6대 섹션(Hero 등) 역할, GitHub Pages 배포의 의미 확인. |
| 시맨틱 태그 | 쓰는 이유(가독성/유지보수 + 스크린리더/검색엔진 접근성)와 `<main>`을 중심으로 한 구조 설계 기준 확인. |
| Flexbox vs Grid | 1차원(한 줄 배치) vs 2차원(바둑판 배치). 기기 종류가 아니라 배치 형태에 따라 선택. |
| DOM 선택과 이벤트 | `querySelector`로 대상을 찾고 `addEventListener`로 감시자를 붙이는 2단계 흐름 확인. |
| 외부 파일 연결 | `<link rel="stylesheet" href="...">`로 CSS, `<script src="..." defer></script>`로 JS 연결. `defer`가 HTML 해석 후 JS 실행을 보장하는 역할 확인. |
| Live Server | 로컬 웹 서버를 열어 파일 변경 시 브라우저를 자동 새로고침하는 개발 도구임을 확인. |

### 1-4. 2026-09-19 Codex 재개 후 확인한 사항

- 사용자가 Google Antigravity로 작업을 이어갔다고 알렸고, Codex가 `codyssey`의 4개 문서와 README·실제 소스 파일을 다시 읽었다.
- 기존 기록의 “HTML 골격 작성 직전”과 달리 실제 `index.html`에는 기본 골격과 CSS/JS 연결이 이미 있었다. 이번 기록에서 이 차이를 바로잡았다.
- README에 실제 진행 상황을 반영하고 `main`에 커밋·푸시했다: `c052f88` (진도 반영), `007b9f9` (자동 새로고침 확인 완료 반영).
- 사용자가 “실시간 새로고침 확인 … 이것도 수행했어”라고 답했다. 이에 따라 README 1단계 전체를 완료로 표시했다.
- 이번 재개 대화에서는 새로운 개념에 대한 이해 확인이나 2단계 코드 작성을 진행하지 않았다. 작업 완료와 개념 이해를 동일하게 판단하지 않는다.
- 사용자가 오늘 기록을 정리하고 내일 미션 상세 학습부터 이어가기를 요청했다.

## 3. 설명한 개념 지도

| 개념 | 소개한 내용 |
| --- | --- |
| HTML | 내용의 역할과 구조를 표시한다. 시맨틱 태그(`<header>`, `<nav>`, `<main>`, `<section>`, `<footer>`)로 구역을 설계한다. |
| CSS | 색상, 크기, 간격, 배치 등 보이는 방식을 정한다. Flexbox(1차원)와 Grid(2차원), 미디어 쿼리로 반응형 레이아웃을 구성한다. |
| JavaScript | 데이터를 다루고 조건을 판단하며 작업을 실행한다. `querySelector`로 요소를 잡고 `addEventListener`로 감시자를 붙인다. |
| 이벤트·상태·DOM | 이벤트는 사용자 행동, 상태는 현재 상황 데이터, DOM은 브라우저 메모리에 올라온 요소들이다. DOM 조작은 파일 원본을 수정하지 않는다. |
| API·비동기 처리 | 외부 서버에 데이터를 요청하고 응답을 기다린다. 로딩, 성공, 빈 결과, 실패(에러) 4가지 상태를 UI로 분기 처리한다. |
| 배포 | 내 컴퓨터(로컬)에서 혼자 열어보기와 GitHub Pages를 통해 전 세계에 공개 URL로 배포하는 것의 차이. |
| 외부 파일 연결 | `<link rel="stylesheet" href="css/style.css">`로 CSS 연결, `<script src="js/script.js" defer></script>`로 JS 연결. `defer` 속성은 HTML 해석이 끝난 뒤 JS를 실행하게 한다. |
| Live Server | VS Code 확장 프로그램. 로컬 웹 서버를 열어 파일 저장 시 브라우저가 자동 새로고침된다. 실시간 개발 확인용 도구. |

### 진행 순서 요약

1. 프로젝트 폴더·파일 생성, HTML 기본 골격 및 CSS/JS 연결 → ✅ 완료
2. Live Server 실행 및 자동 새로고침 확인 → ✅ 완료 (기록 및 사용자 확인 근거)
3. README 진도 반영 및 커밋·푸시 → ✅ 완료
4. **미션 상세를 더 공부하기** → 다음 학습. 시작점 제안은 위 1-2절 참고.
5. 사용자가 준비되면 2단계 HTML 시맨틱 마크업 구현 진행

### 지켜야 할 핵심 맥락

- 미션.md의 **기능 요구사항 순서**를 따라 진행한다 (사용자 요청).
- **미션 상세 학습을 먼저 하고, 그 뒤에 2단계를 구현한다** (2026-09-19 최신 요청).
- HTML/CSS를 먼저 학습·구현하고, JavaScript/API는 뒤로 미룬다 (사용자 합의).
- 방금 설명한 정답을 그대로 되묻는 확인 질문은 하지 않는다 (사용자 강하게 지적).
- 사용자가 먼저 질문하여 확인된 개념은 이해 확인 질문을 생략한다.
- 학습 기록은 사용자 요청 시에만 갱신한다.
