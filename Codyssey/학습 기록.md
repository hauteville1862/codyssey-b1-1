# B1-1 학습 기록

최초 기록일: 2026-09-19
최근 갱신일: 2026-09-19

이 파일은 지금까지의 대화에서 확인된 사용자 설정, 현재 진도, 학습 이력을 정리한 기록이다. 전체 발언의 축어록은 아니다. 모델이 바뀌어도 매 답변 전에 읽고 수업에 적용한다. 사용자의 최신 지시를 우선한다.

## 1. 바로 이어갈 위치와 최근 확인된 진도

- 학습 설정을 마쳤다. 같은 설정 질문을 처음부터 반복하지 않는다.
- **최신 학습 방향 (사용자 최신 요청)**: JavaScript 문법 학습은 잠시 미뤄두고, 실제 구현 순서(황금 법칙: HTML → CSS → JS)에 맞추어 **HTML과 CSS에 해당하는 핵심 요구사항을 먼저 집중적으로 학습**하기로 합의했다.
- 학습과 구현을 병행하는 흐름으로 전환 중이다. 개념만 따로 공부하는 단계에서, 미션.md의 기능 요구사항 순서에 따라 **개념을 배우면서 바로 코드에 반영하는 방식**으로 진행 중이다.

| 파일 연결 (`<link>`, `<script defer>`) | ⏳ 작성 직전 | 개념 설명은 완료. 아래 코드를 `index.html`에 입력하는 것이 바로 다음 작업이다. |

### 1-2. 다음 이어갈 작업 (구체적 지시)

**즉시 할 일**: `index.html`에 HTML5 기본 골격을 작성하고, `<link>`와 `<script defer>`로 CSS/JS 파일을 연결한다.

작성할 코드 (이전 대화에서 제시 완료, 사용자가 직접 입력할지 AI가 반영할지 선택 대기 중이었음):

```html
<!DOCTYPE html>
<html lang="ko">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>나를 소개하는 웹페이지</title>
  <link rel="stylesheet" href="css/style.css">
  <script src="js/script.js" defer></script>
</head>
<body>
  <h1>나를 소개하는 웹페이지</h1>
</body>
</html>
```

- 코드 입력 후 `Ctrl + S`로 저장하면 Live Server가 자동 반영하여 브라우저에 "나를 소개하는 웹페이지" 제목이 나타나는지 확인한다.
- 확인이 되면 README.md 1단계의 "파일 연결"과 "개발 환경 구성" 항목에 ✅를 반영한다.
- 그 다음은 **2단계: HTML 시맨틱 마크업** (`<header>`, `<nav>`, `<main>`, `<section>`, `<footer>`)으로 진입한다.

### 1-3. 이전 대화에서 완료된 개념 확인 이력

아래는 사용자가 자기 말로 설명하거나 질문에 정확히 답하여 이해가 확인된 개념이다.

| 개념 | 확인 방법 및 결과 |
| :--- | :--- |
| 미션 전체 흐름 | `"사용자 이벤트 → DOM 조작 → 화면 변화"` 3단계 흐름을 자기 말로 확인. |
| 외부 API 연동 | GitHub API 실시간 요청 및 4가지 상태(로딩/성공/빈 상태/에러) 구분 확인. |
| 최종 결과물 | 반응형 웹의 의미, 6대 섹션(Hero 등) 역할, GitHub Pages 배포의 의미 확인. |
| 시맨틱 태그 | 쓰는 이유(가독성/유지보수 + 스크린리더/검색엔진 접근성)와 `<main>`을 중심으로 한 구조 설계 기준 확인. |
| Flexbox vs Grid | 1차원(한 줄 배치) vs 2차원(바둑판 배치). 기기 종류가 아니라 배치 형태에 따라 선택. |
| DOM 선택과 이벤트 | `querySelector`로 대상을 찾고 `addEventListener`로 감시자를 붙이는 2단계 흐름 확인. |
| 외부 파일 연결 | `<link rel="stylesheet" href="...">`로 CSS, `<script src="..." defer></script>`로 JS 연결. `defer`가 HTML 해석 후 JS 실행을 보장하는 역할 확인. |
| Live Server | 로컬 웹 서버를 열어 파일 변경 시 브라우저를 자동 새로고침하는 개발 도구임을 확인. |

## 2. 사용자 설정과 목표

| 항목 | 확인된 내용 |
| --- | --- |
| 경험 | 파이썬 교양 수업을 한 학기 수강했다. Claude Code를 이용해 터미널에서 작동하는 간단한 퀴즈 프로그램을 만들었다. |
| 본인의 인식 | "그건 클로드가 만든 거지 내가 만든 게 아니야." AI와 결과물을 만든 경험을 직접 코드를 이해·작성하는 능력으로 간주하지 않는다. |
| 파일 작업 | 파일 만들기·저장하기, 폴더 찾기, 확장자 확인 중 일부가 헷갈린다. 구체적으로 무엇이 어려운지는 아직 확인하지 않았다. |
| 목표 | 배경지식이 없는 사람에게 가르칠 수 있을 정도로 미션을 이해한다. AI가 작성한 코드도 자기 말로 설명할 수 있어야 한다. |
| 희망 일정 | 가능하면 1주 내 개념 학습 후 실제 웹페이지를 만들고 싶다. |
| 학습 시간 | 거의 매일 하루 한 번, 30~40분. |
| 코드 작성 | AI가 대신 작성하는 것은 허용한다. 다만 사용자가 이해할 수 있도록 작은 단위로 설명한다. 설명 요청을 전체 구현 요청으로 확대하지 않는다. |
| 설명 분량 | 내용을 쪼개어 한 번에 이해할 수 있는 만큼만 짧게 답한다. 이 선호가 초기의 긴 개요 설명보다 우선한다. |
| 질문 방식 | 일반 채팅으로 한 번에 하나씩 묻는다. 사용자가 먼저 질문하여 확인된 개념은 동일한 내용을 되묻는 확인 퀴즈를 생략한다. |
| 기록 관리 | 매 턴마다 파일을 수정하지 않고, 사용자가 요청할 때 한 번에 모아서 갱신한다. |
| 모델 선택 | 개념 학습 단계의 빠른 문답 호흡과 토큰 효율을 위해 Gemini Flash 계열을 추천함. Astra보다 낮은 모델 사용 선호. |

## 3. 설명한 개념 지도

| 개념 | 소개한 내용 |
| --- | --- |
| HTML | 내용의 역할과 구조를 표시한다. 시맨틱 태그(`<header>`, `<nav>`, `<main>`, `<section>`, `<footer>`)로 구역을 설계한다. |
| CSS | 색상, 크기, 간격, 배치 등 보이는 방식을 정한다. Flexbox(1차원)와 Grid(2차원), 미디어 쿼리로 반응형 레이아웃을 구성한다. |
| JavaScript | 데이터를 다루고 조건을 판단하며 작업을 실행한다. `querySelector`로 요소를 잡고 `addEventListener`로 감시자를 붙인다. |
| 이벤트·상태·DOM | 이벤트는 사용자 행동, 상태는 현재 상황 데이터, DOM은 브라우저 메모리에 올라온 요소들이다. DOM 조작은 파일 원본을 수정하지 않는다. |
| API·비동기 처리 | 외부 서버에 데이터를 요청하고 응답을 기다린다. 로딩, 성공, 빈 결과, 실패(에러) 4가지 상태를 UI로 분기 처리한다. |
| 배포 | 내 컴퓨터(로컬)에서 혼자 열어보기와 GitHub Pages를 통해 전 세계에 공개 URL로 배포하는 것의 차이. |
| 외부 파일 연결 | `<link rel="stylesheet" href="css/style.css">`로 CSS 연결, `<script src="js/script.js" defer></script>`로 JS 연결. `defer` 속성은 HTML 해석이 끝난 뒤 JS를 실행하게 한다. |
| Live Server | VS Code 확장 프로그램. 로컬 웹 서버를 열어 파일 저장 시 브라우저가 자동 새로고침된다. 실시간 개발 확인용 도구. |

### 진행 순서 요약

1. ~~프로젝트 폴더·파일 생성~~ → ✅ 완료
2. **`index.html`에 HTML5 골격 + CSS/JS 파일 연결 코드 작성** → ⏳ 바로 다음
3. Live Server로 브라우저 확인 → ✅ 환경 준비 완료
4. README.md 1단계 나머지 항목 ✅ 반영
5. 2단계: HTML 시맨틱 마크업 (6대 섹션 뼈대) 진입

### 지켜야 할 핵심 맥락

- 미션.md의 **기능 요구사항 순서**를 따라 진행한다 (사용자 요청).
- HTML/CSS를 먼저 학습·구현하고, JavaScript/API는 뒤로 미룬다 (사용자 합의).
- 방금 설명한 정답을 그대로 되묻는 확인 질문은 하지 않는다 (사용자 강하게 지적).
- 사용자가 먼저 질문하여 확인된 개념은 이해 확인 질문을 생략한다.
- 학습 기록은 사용자 요청 시에만 갱신한다.
